# CTF 週報呈現決策

本文件是 CTF 公開週報的版面契約。後續修改必須先更新本文件及對應測試，不能只因版面看似更短，就改變成員查找特定日期賽事的方式。

## 必須達成的使用情境

成員應能直接找到本週任一指定日期，例如 `9/26（六）`，並在該日期區塊內完成以下事情：

1. 看見當日仍在進行或即將開始的全部 CTF。
2. 看見每場在該日的開始、結束或持續狀態。
3. 看見來源能證實的紅隊、藍隊及最多三項代表技術。
4. 點一次活動名稱便開啟官方頁面。

成員不得為了完成以上任務而比較日期區間、從活動清單自行篩選、上下交叉對照兩塊內容，或先操作日期選單再尋找活動連結。

## 已採用的結構

- 公開頻道每週只建立一則 CTF 週報；同週資料變更只編輯原訊息。
- 週報以台灣時間的絕對日期分段，順序固定為星期一至星期日。
- 只建立有賽事或已確認期限的日期區塊；不顯示「沒有賽事」的空日期。
- 每個日期區塊必須能獨立閱讀。跨日賽事刻意出現在涵蓋的每一天，這是為了避免成員自行計算日期區間，不視為需要消除的重複。
- 活動名稱本身是官方網址的 Markdown 連結；基本查找流程不得依賴額外按鈕、選單或私人回覆。
- 每場以該日期為基準顯示開始時間、結束時間或持續進行狀態。日期邊界使用絕對日期與星期，不使用「今天」或「明天」。
- 有可靠證據時，在同一日期區塊顯示攻防方向與最多三項技術；同時具有紅藍證據時，技術項目至少保留一項攻擊面與一項防禦面。證據不足時整個欄位省略，不以「綜合」代替未知。
- 「完整 CTF 賽程」只能作為遠期或補充資料入口，不能成為查看當週指定日期所必須經過的步驟。

## 明確否決的方案

### 依活動排序的單一清單

否決。成員若想查看星期六，必須逐筆判斷每場活動的日期範圍；這把系統應完成的篩選工作轉嫁給讀者。

### 上方日期索引、下方活動詳情

否決。同一資訊被拆成兩塊，成員必須先在索引找到名稱，再到詳情區尋找第二次，增加上下對照成本。

### 日期選單、日期按鈕或互動式分頁

否決作為主要介面。查看單一活動會變成「選擇日期，再點活動連結」兩步，而且看不到其他日期的內容。互動元件只能提供補充功能，不能取代公開日期區塊。

### 依「進行中／稍後開始／接下來」分段

否決。這些分類會隨時間改變，同一則週報跨過午夜後語意不同；成員也無法直接定位指定日期。

### 使用「今天／明天」等相對日期

否決。成員在 23:59 與 00:00 閱讀會得到不同解讀，公告內容也無法在整週維持穩定語意。

### 為消除重複而只列跨日賽事一次

否決。這會讓其他日期區塊不完整。跨日賽事在每個涵蓋日期重複，是日期優先導航的必要成本。

### 每天重新發送一則 CTF 公告

否決。會增加通知疲勞及頻道洗版風險。每週只建立一則訊息，資料更正時編輯原訊息。

## 驗收條件

任何版面修改至少需要測試並確認：

1. 沒有賽事的日期不產生公開區塊。
2. 指定日期的區塊包含當日所有跨日與當日開始的賽事。
3. 同一日期區塊不依賴其他區塊才能判斷賽事時間與技術方向。
4. 公開活動名稱可直接連至官方頁面，不增加中間互動步驟。
5. 公告不使用「今天」「明天」等會在午夜改變語意的詞。
6. 來源沒有分類證據時不顯示猜測的方向或技術。
7. 同週格式或資料更新會編輯既有訊息，不建立第二則週報。

若新方案無法同時通過以上條件，就不能取代目前的日期分段結構。
