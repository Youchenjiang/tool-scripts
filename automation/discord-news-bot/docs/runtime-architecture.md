# Bot 執行期架構

## 目標

維持單一 Discord Bot 與單一 Northflank service，同時讓新聞、活動及共用執行期可以獨立維護與失敗隔離。重構期間不得改變既有指令文字、公開訊息格式、頻道、去重資料或資料庫結構。

## 模組邊界

### 共用執行期

- 建立 Discord client、登入及關閉 state store。
- 啟動具名稱的週期工作，統一記錄成功與錯誤。
- 將 Discord interaction 依功能交給新聞或活動入口。
- 單一功能初始化失敗時保留其他已完成初始化的功能。

### 新聞功能

- 初始化新聞頻道、publisher、規則設定及來源觀察。
- 處理新聞狀態、立即檢查、AI 供應商檢查及規則設定。
- 新聞抓取、AI 判斷與技術細節仍由既有領域模組負責。

### 活動功能

- 初始化活動頻道與 event service。
- 處理活動狀態、立即更新、總表互動及個人訂閱。
- 活動蒐集、總表、非 CTF 即時公告、CTF 週報及提醒維持獨立階段。

## 排程政策

- 新聞與活動可維持不同的檢查週期，不互相阻塞。
- 非 CTF 活動在新資料通過範圍與去重規則後發布。
- CTF 只建立每週週報；同週資料變化編輯原訊息。
- 排程規則只能存在一份正式實作；停用或未接線的舊流程必須移除或完成遷移。

## 可觀測性

每次工作至少記錄工作名稱、觸發來源、檢查數量、發現數量、發布數量、來源錯誤及完成時間。來源與發布統計不可包含 token、資料庫連線字串或私人互動內容。

## 原子化遷移順序

1. 抽出共用週期工作，不改變執行頻率。
2. 抽出活動 interaction 入口，不改變回覆內容。
3. 抽出新聞 interaction 入口，不改變回覆內容。
4. 隔離新聞與活動初始化失敗，不改變正常路徑。
5. 統一正式活動排程，另行移除未使用的舊入口。
6. 增加結構化統計，不與排程或訊息格式調整混合。

每一步均需獨立提交，並保持完整測試套件通過。
